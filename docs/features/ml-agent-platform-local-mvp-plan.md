## 目标与职责

将 k_agent 扩展为对话驱动的专用机器学习平台，支持数据集发现、数据处理、训练、调参、成果评估与应用部署。

Agent 负责理解业务目标、规划、调用工具、解释结果。平台负责独立于聊天记录的真实状态、持久执行、资源管理与模型发布。对话结束不能终止训练；聊天内容不能代替运行记录或模型状态。

## 待补平台能力

1. 将业务目标转为预测任务、指标、基线、预算与验收条件。
2. 内部与公开数据发现，核查权限与许可，记录质量、版本、加工过程和血缘。
3. 支持有依赖关系的流水线，以及取消、重试、恢复和产物复用。
4. 本地隔离环境、依赖与 CPU/GPU 管理，异步训练日志、检查点、并发限制及资源预算。训练生命周期独立于聊天连接。
5. 实验关联数据、代码、环境、参数、指标和模型，比较候选，并按预算早停。
6. 固定测试集，检查数据泄漏，比较基线，评估分群误差、稳定性、延迟和成本。
7. 模型版本管理、批量与在线推理、发布检查、灰度、回滚和漂移监测。
8. 在对话内展示流水线、训练曲线、实验对比与评估报告；Web 和独立 CLI 同步功能、必要信息、状态及行为语义。

## 核心持久对象

任务、数据集版本、流水线版本、运行记录、实验、模型版本、评估报告、部署记录。对象之间应关联，并可追溯到数据、代码和配置来源。执行状态由平台持久化，不依赖聊天是否在线。

MLflow、Kubeflow 和 Ray Tune 仅为后续候选参考，不是已选定依赖，本次不引入。

## 第一版本地资源边界

第一版仅本地运行，不上云。用户自述机器为 8GB 显存 RTX 5060，愿意分配约 3～4GB 显存给训练。这是用户提供的机器信息，不是当前开发机探测结果。

3～4GB 是方案起点。应先短跑测量显存峰值，再调整 batch size、模型与训练配置。未实测前，不保证具体显存占用、耗时或准确率。

预算应包含 CUDA 上下文、缓存和其他进程的占用，依实测监控和执行管理约束。仅限制 batch size 或框架缓存，不能视作显存硬隔离。第一版采用串行训练，避免多实验争抢有限显存。

## 建议样例与实验流程

建议以 CIFAR-10 十类图片分类为样例。先建立小型 CNN 基线，后续可比较适配小图片的 ResNet-18。

首轮固定抽取约 5000 张训练图片，另取不重叠的验证样本；记录抽样种子和样本标识。官方测试集固定保留，仅用于最终评估，不参与调参。

batch size 从 32 起步。先做短跑，测量峰值显存和耗时，再确定实验配置。安排约 4～6 组学习率、正则与数据增强实验。运行前明确总时长、单次时长及显存预算；具体阈值待实测与用户确认。

实验记录准确率、每类指标、混淆矩阵、错误样例、耗时和峰值显存，并保存数据版本、代码版本、环境和参数。根据验证集结果和资源成本解释选型，最终对指定候选执行一次固定测试集评估。

## 本地应用与发布

提供本地预测接口和小图片演示，优先使用 CPU 推理，降低与训练的显存竞争。演示针对指定任务和输入范围，不承诺对任意真实图片的泛化能力。

发布指定模型版本，记录评估与发布依据，支持回滚至已知版本。后续在线发布、灰度和漂移监测需另行细化边界和验收。

## 首版验收与后续范围

首版应形成完整、可复现、可取消和恢复、可追溯的流程，能够解释候选选型、部署指定模型版本并回滚。

数据下载与登记纳入首版。跨网站自主搜集与筛选数据、大规模调参、自动重训练，作为后续独立任务与独立验收，不隐含纳入第一版。
