# 对话区底部终端技术方案

> 状态：已按本文实现。收起底栏保持连接；换会话或离开页面才结束 PTY。  
> 适用范围：K Agent 本地 Work 对话页  
> 编写日期：2026-10-06

## 1. 结论

在「切换右侧面板」按钮左侧增加一个按钮，点击后在对话区下方打开终端。布局上可行，并且只应占用对话列，不延伸到会话列表和右侧工作区下面。

现有 Agent Bash 工具是一次性命令，不能当作这个交互终端。用户终端需要单独的 PTY 和 WebSocket，由 Access Layer 持有，Agent Backend 不参与。

## 2. 现状

页面是三列网格，定义在 `frontend/src/styles.css` 的 `.shell`：

```text
会话列表 | 对话列 | 右侧工作区
```

对话列 `.conversation` 是纵向 flex：顶栏、消息流、输入框。右侧栏开关是顶栏里的 `topbar-icon-button`，文案为「切换右侧面板」，只在 Work 对话页显示。右侧栏宽度已经用 CSS 变量和拖动条记住。

`backend/tools/builtins/shell.py` 的 Bash 工具通过 `asyncio` 子进程执行一条命令，带超时，输出进入 Agent 运行。它没有持久标准输入，也没有和浏览器共享的终端画面。

Access Layer 拥有会话和工作区；Agent Backend 只做模型和工具执行。两边只通过 HTTP 通信，不能互相导入。

## 3. 目标与首版边界

### 3.1 目标

- 顶栏右侧按钮左边有一枚同尺寸的底栏按钮。
- 打开后，终端出现在输入框下面，宽度等于对话列。
- 终端高度可拖动，并在本地记住。
- 用户可以在该会话工作区里交互式输入命令，并看到持续输出。

### 3.2 首版包含

- 一个终端，绑定当前对话会话的工作区目录。
- 输入、输出、行列变化、进程退出。
- 收起面板时进程继续运行；再次打开仍是同一个终端。
- 切换会话或离开页面时结束该进程。

### 3.3 首版不包含

- 多个终端页签。
- 把终端输出写入 Agent 对话。
- 让 Agent 读取或向这个终端写命令。
- 复用 Bash 工具的沙箱、超时和审批。
- 系统级常驻终端服务。

## 4. 布局

按钮放在 `frontend/src/App.tsx` 顶栏 `.topbar-actions` 内，紧挨「切换右侧面板」左侧。图标沿用现有侧栏图标的画法，方向改为底栏。只在 Work 对话页渲染。

对话列内部改为：

```text
顶栏
消息流（占剩余高度）
输入框
拖动条
终端（打开时占 --terminal-height）
```

终端不进入 `.shell` 的三列网格，因此不会铺到会话列表或工作区下面。

高度建议：

- 默认约 240px。
- 最小约 120px。
- 最大不超过对话列高度的一半，保证消息和输入框仍可见。
- 用与 `--inspector-width` 相同的方式持久化，例如 `localStorage` 键 `k-agent-terminal-height`，开关状态单独保存。

窄屏沿用现有 860px 断点。该宽度下右侧栏已改为抽屉，底栏不再和消息上下分屏，改为从对话列底部升起的一层。

## 5. 终端通道

WebSocket 只出现在浏览器和 Access Layer 之间，路径是 `/api/sessions/{sessionId}/terminal`。对话消息、模型调用、Agent Bash 仍走现有 HTTP，不改成 WebSocket。

终端打开后，按键和命令输出会连续发生，而且方向是双向的：浏览器要随时把按键送进去，服务要随时把 PTY 输出推出来。一次 HTTP 请求只能表达「发出去，再等一次完整响应」。用短轮询会把按键和输出切成一段段请求，光标、Ctrl-C 和全屏程序都会卡。WebSocket 把这条连接保持住，双方可以交错发送第 5.3 节的四种消息，直到会话切换或页面关闭。

### 5.1 前端

使用 xterm.js 渲染，配合 FitAddon 把容器尺寸换成终端行列。面板打开后再连接；容器尺寸变化时发送新的行列。

### 5.2 归属

WebSocket 挂在 Access Layer。会话和工作区目录已经在这里，终端进程与会话一起管理。Agent Backend 不新增终端接口，继续只处理模型和工具。

同一对话会话可以开多块终端，每块一个 PTY，标签上显示 shell 名。工作目录是该会话工作区，shell 使用用户登录 shell。只有用户打开底栏或点击加号才创建进程。

### 5.3 消息

连接路径为 `/api/sessions/{sessionId}/terminal/{terminalId}`。消息四种：

| 方向 | 类型 | 内容 |
| --- | --- | --- |
| 浏览器 → 服务 | input | 用户按键字节 |
| 服务 → 浏览器 | output | PTY 输出字节 |
| 浏览器 → 服务 | resize | 列数、行数 |
| 服务 → 浏览器 | exit | 退出码 |

输出按字节转发，不解析命令。连接断开或会话切换时，Access Layer 关闭对应 PTY。

## 6. 与 Agent Bash 的关系

两条通道同时存在，职责不同：

| | 用户终端 | Agent Bash |
| --- | --- | --- |
| 谁发起 | 用户在底栏输入 | 模型调用工具 |
| 生命周期 | 面板打开期间持续存在 | 一条命令，到超时或结束 |
| 输出去向 | 终端画面 | 对话里的工具结果 |
| 权限 | 用户显式打开的宿主机 shell | 现有沙箱与审批 |

两者可以使用同一个工作区目录，因此会看到对方正在修改的文件。终端标题显示当前目录。终端权限高于沙箱命令，所以不能随会话自动启动。

## 7. 实施顺序

1. **面板壳**：按钮、底栏、拖动高度和空状态。确认消息滚动、输入框和右侧栏互不遮挡。
2. **PTY**：Access Layer 创建进程，WebSocket 打通输入、输出和缩放。
3. **生命周期与窄屏**：会话切换和页面关闭时回收进程；窄屏改为底部抽屉。

第 1 步不依赖终端进程，可以单独落地。

## 8. 风险

- 宿主机 shell 可以执行任意本地命令。首版依赖「用户自己点开」作为授权，不另做命令审批。
- PTY 输出可能很大。WebSocket 只转发当前画面所需字节，不把滚动历史写入会话事件。
- 输入法组合字符需要在 xterm.js 里单独验证，避免和对话输入框抢焦点。
