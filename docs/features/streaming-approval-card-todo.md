## 1. 问题描述

当前存在一个持续未解决的问题：当模型在流式输出过程中触发审批或工具相关卡片时，前端卡片不会实时渲染出来，通常要等刷新页面后才出现。

用户已经明确反馈过以下现象：

- 流式过程中卡片不出现。
- 刷新后卡片才出现。
- 说明问题不是“卡片数据没有持久化”，而是“实时事件没有被前端正确消费或投影”。
- 目前相关的审批/权限升级流程触发方式仍然不正确，前端没有在事件到达时即时渲染对应 UI。

## 2. 目标

把审批卡片、工具审批卡片、权限相关卡片在流式阶段正确渲染出来，要求：

- 事件到达后即时出现在当前 transcript 中。
- 刷新前后表现一致。
- 不依赖刷新作为补救手段。
- 卡片的可见状态、折叠状态和时间线位置都能被正确恢复。

## 3. 当前待查方向

### 3.1 事件链路

需要继续核对以下链路是否完整：

1. 后端是否真的发出了正确的 AG-UI 事件。
2. Access Layer 是否把事件转成了前端能消费的 SSE/HTTP 流。
3. 前端是否在流式中把该事件纳入 transcript state。
4. `ConversationTranscript` 是否只在刷新后基于历史快照渲染，而不是实时订阅渲染。

### 3.2 可能的断点

- 事件类型没有注册到统一的 AG-UI 事件分发器。
- 事件虽然持久化了，但没有进入当前运行中的前端 state。
- 前端在流式阶段对卡片类节点做了延迟批处理，导致刷新后才从历史消息重建。
- `ConversationTranscript.tsx` 相关渲染逻辑存在条件分支，只有在 session reload 时才走到审批卡片分支。
- 事件在流中到达顺序正确，但没有触发 React 重新布局或新的节点 append。

## 4. 需要修复的原则

- 不要靠“刷新恢复”掩盖实时渲染失败。
- 不要把审批/工具卡片只做成历史回放逻辑。
- 不要改成需要手动重新打开会话才能看到卡片。
- 审批流程必须和普通流式消息共享同一条实时事件投影链路。

## 5. 验收标准

修复完成后，需要满足：

- 在工具请求发生后，审批卡片能在当前页面实时出现。
- 不刷新页面也能看到完整卡片。
- 触发暂停、拒绝、允许、超时等状态变化时，卡片能实时更新。
- 刷新页面后，卡片状态与流式期间看到的一致。
- 手动结束会话后，当前 transcript 停止更新并保留最终状态。

## 6. 后续排查建议

- 先确认后端 AG-UI 事件类型是否已经进入统一事件枚举。
- 再检查 Access Layer 的事件转发和前端订阅是否一致。
- 最后核对 `ConversationTranscript.tsx` 是否在流式阶段就能消费这些事件，而不是只读静态 session 快照。
